{% comment %} Toasts are the single place server-side feedback appears, so every screen gets the same behaviour for free. NOTE: this has to be a comment block tag rather than a single-brace comment. Django's single-brace comment is not DOTALL, so a newline inside it makes the lexer give up and emit the whole block as literal text on every page. That bug shipped once already, and was reintroduced once while fixing it; test_the_page_never_leaks_a_template_comment pins it. Two sources feed it: * `messages` -- session messages raised by views (approval outcomes, "your account is not approved", forced password change). * `form` -- this page's own bound form. A field error is already rendered inline by the form template; the toast repeats it so it is noticed without scrolling. Both are marked data-toast--persistent when they carry an error or a warning. A message the user still has to act on must not scroll away because they were slow to look at it: it stays until dismissed or the page changes. Confirmations ("Approved.") are transient and do drain. Everything is server-rendered and visible with JavaScript disabled: without JS the toast stays put instead of draining away. The .js class on is what switches the countdown on, so the animation never starts for a browser that cannot dismiss anything. {% endcomment %} {% if messages or form.errors %}
