{% extends "base.html" %} {% block title %}Approvals · Avanyam LMS{% endblock %} {% comment %} The approval screen, and the whole reason an admin has one. Every admin sees the same queue: there is no per-trainer split any more (D41), so there is nothing on this page to filter by and no row that is "mine" rather than "yours". Three deliberate choices: * Status tabs instead of one long list. "Pending" is what needs action; approved and declined are history you occasionally want to check, not scroll past. The counts come from the view over the same rows that are rendered, so a tab can never claim "3 pending" above a list of five. * The role control sits in the decision form, above the buttons, and defaults to what the applicant asked for. It is not a separate action because it is not one: approving with a different role is still one approval, and it is recorded as an override on the same row. * The note field is here rather than in a modal. A dialog would have to trap keyboard users to be dismissable, and the thing being confirmed -- declining someone's registration and permanently blocking that address -- deserves to be visible in the page, not behind a click. {% endcomment %} {% block content %}
